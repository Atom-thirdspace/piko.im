Piko for developers

A read-only HTTP API over the problem set, the courses, and your own activity. Built for people who want to poke at it — scrape the catalog, chart your streak, wire it into an editor.

Version {{ version }} · base URL /api/v1

Getting a key

The catalog works with no key at all. A key raises your rate limit and unlocks the /me endpoints. {% if current_user() %} Create one in settings. {% else %} Sign in to create one. {% endif %} 

curl -H "Authorization: Bearer piko_sk_..." \
  {{ request.host_url }}api/v1/me

A key is shown once, when you create it. We store only a hash, so if you lose it there is nothing to recover — revoke it and make another. Treat it like a password: not in a public repo, not in front-end JavaScript, where anyone viewing the page can read it.

Scopes

You pick these when creating the key. A key only carries what you ticked.

Pagination

List endpoints take page (from 1) and per_page (default {{ default_per_page }}, max {{ max_per_page }}), and answer with items alongside page, per_page, total and pages.

Errors

Failures are {"error": {"code": ..., "message": ...}}.

CodeHTTPMeaning
bad_token401 The key is unknown, revoked, or expired.
no_token401 That endpoint needs a key and none was sent.
missing_scope403 Valid key, but it does not carry the scope.
rate_limited429 Slow down. See Retry-After.
not_found404 No such resource, or it is not published.
unavailable503 The database is unreachable.

Caching

Catalog responses carry an ETag and are cacheable for five minutes. Send If-None-Match and a match costs you a 304 instead of a payload — and does not count any less against your rate limit, so cache locally too. /me responses are private, no-store.

Rules

  • Read-only. Nothing in the API changes anything.
  • Hidden tests, hints, quiz answer keys and unpublished drafts are never served.
  • One key per project, so you can revoke one without breaking the rest.
  • Identify yourself with a User-Agent if you are writing a bot.
